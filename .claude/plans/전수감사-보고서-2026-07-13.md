## 핵심 결론 (BLUF)

**이 프로젝트의 `.claude/` 설정 대부분은 "hotseller erp" 프로젝트에서 복사된 뒤 정리되지 않았다.**

존재하지 않는 스킬/스크립트를 가리키는 깨진 참조가 14곳, 글로벌↔프로젝트 규칙 정면 상충이 4건 있다.
하위 모델은 이런 모순된 지시를 스스로 걸러내지 못하므로, **삭제 21건 + 재작성 9건 + 수정 18건**을 권고한다.

## H. 하위 모델 전환 대비 권고 (우선순위 순)

1. **1순위 — 모순 제거 (D 섹션)**: 하위 모델은 상충 지시를 만나면 임의로 한쪽을 고르거나 얼어붙음. 글로벌/프로젝트 agent-spawn 통일이 가장 급함.
2. **2순위 — 깨진 참조 제거 (C 섹션)**: 존재하지 않는 스킬·스크립트 호출은 하위 모델이 재시도를 반복하며 토큰을 태우는 대표 패턴.
3. **3순위 — ERP 잔재 삭제 (A 섹션)**: 무관한 도메인 지식이 컨텍스트를 오염 — 하위 모델일수록 잘못된 유추(예: Firestore 프로젝트에 SQL 트랜잭션 적용) 위험 큼.
4. **4순위 — 재작성 (B 섹션)**: test-runner의 pytest 누락이 가장 실질적 (검증 게이트가 Python 코드를 전혀 검증하지 않음).
5. **모델 표기 원칙**: 룰에 모델 버전명을 하드코딩하지 말고 역할(메인/워커/리뷰어)로 기술 — 모델 교체 시 룰 개정 불필요.
6. **스킬 정책**: 글로벌엔 범용 스킬만, 도메인 스킬은 각 프로젝트 로컬에 — "어느 프로젝트에서 열어도 안전한가"를 글로벌 승격 기준으로.
