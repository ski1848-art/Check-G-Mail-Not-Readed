# PRD Writer

`/prd-writer` 또는 PRD/스펙 문서 작성이 필요할 때 활성화.

## 목적

AI 코딩 어시스턴트가 **효과적으로 실행할 수 있는** PRD를 작성한다.
기존 `/feature-planning`이 ERP 내부 워크플로우용이라면, 이 스킬은 **문서 품질 자체**에 집중한다.

## 핵심 원칙: AI 최적화 PRD

**전통적 PRD가 AI에서 실패하는 이유: 맥락을 추론하는 인간 독자용으로 작성되기 때문.**

AI 코딩 어시스턴트에게 필요한 것:
- **순차적, 의존성 기반 페이즈** (기능별 분류가 아닌 실행 순서)
- **명시적 경계** (AI는 생략에서 추론하지 못함)
- **테스트 가능한 수락 기준** (모호한 성공 정의 금지)
- **적정 작업 단위** (프론티어 LLM 기준 페이즈당 5~15분)

## 100점 프레임워크

### AI 최적화 (25점)

**순차적 페이즈 구조 (10점)**
- 의존성 순서로 정렬된 페이즈
- 페이즈당 5~15분 AI 작업량
- 기반 → 고급 기능 순서
- 접두사: FR-LD (로컬개발), FR-PT (플러그인/테마), FR-CM (컨텐츠), FR-DP (배포)

**명시적 Non-Goals & 경계 (8점)**
- "Non-Goals" 섹션에 만들지 않을 것 명시
- 경계를 긍정형으로: "인증은 Phase 1 범위 밖"
- AI가 생략에서 한계를 추론할 것이라 가정 금지

**구조화된 문서 형식 (7점)**
- 12~16개 주요 섹션, 명확한 헤더
- 일관된 포맷
- "literal-minded" AI가 파싱하기 쉬운 구조

### 전통 PRD 핵심 (25점)

**문제 정의 & 컨텍스트 (7점)**
- 정량화된 페인 포인트, 구체적 메트릭
- 시장 컨텍스트, 경쟁 환경
- "왜 지금" 근거

**목표 & 성공 메트릭 (8점)**
- SMART 목표, 베이스라인 vs 타겟
- P0(필수) / P1(권장) 메트릭 분리
- 측정을 위한 계측 요건

**타겟 오디언스 & 페르소나 (5점)**
- 2~4개 상세 페르소나: 배경, 경험, 목표, 페인 포인트, 유스케이스

**기술 사양 (5점)**
- 버전 요구사항, 호환성 매트릭스, 성능 임계값

### 구현 명확성 (30점)

**기능 요구사항 (10점)**
- 고유 ID: FR-XX-001, FR-XX-002
- 우선순위: P0 (must-have), P1 (should-have), P2 (nice-to-have)
- 요구사항별 수락 기준
- 예시 입력/출력

**비기능 요구사항 (5점)**
- 보안, 성능, 신뢰성, 유지보수성

**기술 아키텍처 (10점)**
- ASCII 또는 Mermaid 다이어그램
- 통합 포인트, 데이터 플로우
- API 계약, 데이터 모델

**구현 페이즈 (5점)**
- 3~5개 페이즈, 명확한 마일스톤
- 페이즈 간 의존성 명시
- 페이즈별 산출물

### 완성도 & 품질 (20점)

**리스크 평가 (5점)** — 확률 x 영향 매트릭스, 완화 전략
**의존성 (3점)** — 외부/내부, 차단/비차단 분류
**예시 & 템플릿 (7점)** — 코드 샘플, 설정 예시, API 요청/응답
**문서 품질 (5점)** — 전문적 포맷, 용어 사전

## PRD 템플릿

```markdown
# Product Requirements Document: [Feature Name]

**Status:** Draft | Review | Approved

---

## 1. Executive Summary and Vision
## 2. Problem Statement
## 3. Goals and Success Metrics
## 4. Non-Goals and Boundaries
## 5. User Personas and Use Cases
## 6. Functional Requirements (FR-XX-001 형식, P0/P1/P2)
## 7. Non-Functional Requirements
## 8. Technical Architecture
## 9. Implementation Phases
## 10. Risk Assessment
## 11. Dependencies
## 12. Appendices (용어사전, 참고자료)
```

## 행동 특성
- **페이즈 우선 사고**: 기능 카테고리가 아닌 구현 순서로 정리
- **명시적 > 암묵적**: 경계를 긍정형으로 선언, AI 추론에 의존하지 않음
- **테스트 가능한 결과**: 모든 요구사항에 수락 기준
- **적정 단위**: 5~15분 AI 실행 가능 단위로 분할
- **우선순위 규율**: 모든 요구사항에 P0/P1/P2
- **예시 기반**: 추상적 개념마다 구체적 예시

## 응답 접근법

1. **범위 명확화** — 포함/명시적 제외 사항
2. **페르소나 식별** — 사용자, 필요 사항
3. **페이즈 정의** — 순차적, 의존성 기반 작업 단위
4. **요구사항 작성** — FR 코드, 우선순위, 수락 기준
5. **예시 추가** — 요구사항별 구체적 입출력
6. **리스크 평가** — 문제 가능성, 완화 방안
7. **셀프 채점** — 100점 프레임워크 대비 검증

## ERP 프로젝트 적용 시 주의
- ERP의 `/feature-planning`은 스펙→태스크→구현 **워크플로우**
- 이 스킬은 그 워크플로우에 투입되는 **PRD 문서 자체의 품질**을 높이는 것
- 작성된 PRD는 `.claude/plans/` 경로에 보존
