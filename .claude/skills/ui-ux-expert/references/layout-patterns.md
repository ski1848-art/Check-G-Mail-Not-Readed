# Layout Patterns — 레이아웃 설계 가이드

> 출처: Vercel Web Interface Guidelines, UI/UX Pro Max Skill, 프로젝트 실전 경험

## 모달 크기 기준

| 콘텐츠 복잡도 | max-width | 예시 |
|-------------|-----------|------|
| 단순 확인/입력 | 480px | 삭제 확인, 단일 필드 입력 |
| 표준 폼 | 640px | 거래처 등록, 계정과목 편집 |
| 복잡한 폼 | 900px | 세금계산서 발행 |
| 대형 데이터 | 1200px | 다중 패널, 매칭 화면 |
| 최대 (예외) | 1400px | 4+ 영역 동시 표시 (권한 설정 등) |

> **데스크톱(md+)**: `max-w-[95vw]` 금지, 1400px 초과 금지.
> **모바일(md 미만)**: `w-full max-w-[95vw]` 허용. 상세 → `responsive-design.md`

## 그리드 열 비율 원칙 (Vercel Guidelines 기반)

### 고정폭 vs 유동폭
- 콘텐츠 크기 일정 (체크박스, 토글, 배지) → **고정폭** (px)
- 콘텐츠 크기 가변 (이름, 설명, 목록) → **유동폭** (fr, minmax)
- **최소 1개 열은 반드시 유동폭** — 모두 고정이면 빈 공간/오버플로우 발생

### 다열 레이아웃 비율
| 패턴 | 비율 | 용도 |
|------|------|------|
| 사이드+메인 | 240px + 1fr | 설정 메뉴 + 콘텐츠 |
| 3열 설정 | 200-220px + 180-200px + 1fr | 카테고리 + 옵션 + 상세 |
| 2열 폼 | 1fr + 1fr | 좌우 균등 입력 필드 |
| 마스터-디테일 | 35% + 65% | 목록 + 상세 |

### 열 최소 너비
| 용도 | 최소 | 권장 |
|------|------|------|
| 체크박스 열 | 40px | 40px |
| 토글/상태 열 | 60px | 80px |
| 이름 열 | 120px | 160px+ |
| 액션 열 | 60px | 80-100px |

## 테이블 열 비율 (Carbon Design 참고)

### 기본 원칙
1. 첫 열(체크박스+이름) → 가장 넓게: `1fr` 또는 `minmax(200px, 1fr)`
2. 상태/토글 열 → 고정폭: `80px`
3. 상세 정보 열 → 유동: `minmax(150px, 1fr)`

### 안티패턴
- ❌ `grid-cols-[1fr_72px_160px]` — 마지막 열만 고정 → 비율 불균형
- ❌ 모든 열 고정폭 → 반응형 깨짐
- ❌ `auto` 남용 → 콘텐츠에 따라 레이아웃 흔들림

## 높이 균일성 원칙

1. **테이블 행은 반드시 높이 균일** — 콘텐츠 양에 따라 달라지면 안 됨
2. 가변 콘텐츠는 **아코디언/펼치기**로 분리 (행 높이 영향 없이)
3. 가변 콘텐츠를 인라인으로 표시하면 높이 불균일 → AP-L2 위반
4. **동일 행(1라인 컨테이너) 내 모든 셀은 세로 높이·세로 정렬 반드시 일치** — 같은 `<tr>`, flex row, grid row 안의 셀이 서로 다른 높이를 가지면 안 됨. padding, border, inner element 등 모든 요소를 합산하여 최종 렌더 높이를 맞출 것
5. **공용 컴포넌트는 props로 높이 개별 세팅** — 여러 컨텍스트(필터, 테이블 인라인, 모달 등)에서 재사용되는 공용 컴포넌트의 높이/padding 조정은 props(예: `size`, `compact`)로 제어하여 다른 사용처에 영향 없도록 할 것. CSS `!important` override에 의존하지 말고 컴포넌트 자체가 컨텍스트별 크기를 지원해야 함

## 공간 배분

### 섹션 간 구분
- 같은 그룹 내: `gap-1` ~ `gap-2`
- 다른 그룹 간: `gap-4` 또는 `border-b`
- 독립 영역: `border` + `rounded-lg` + `p-3`

### 모달 내부 패딩
| 영역 | 패딩 |
|------|------|
| 헤더 | `px-4 py-2.5` |
| 섹션 헤더 | `px-3 py-2 bg-gray-50` |
| 리스트 아이템 | `px-3 py-2` |
| 푸터 | `px-6 py-3` |

## 정보 밀도 (Pro Max Skill 참고)

| 모드 | 행 높이 | 폰트 | 간격 | 본문 최소 폰트 |
|------|--------|------|------|-------------|
| Compact | 32-36px | text-xs | gap-1~2 | 12px |
| Standard | 40-48px | text-sm | gap-2~3 | 14px |
| Spacious | 48-56px | text-base | gap-3~4 | 16px |

> Pro Max Rule #5: 본문 최소 16px — ERP Compact 모드에서는 12px까지 허용 (내부 시스템 예외)

## 모바일 레이아웃 규칙

### 브레이크포인트별 모달 너비
| 콘텐츠 복잡도 | 모바일 (md 미만) | 데스크톱 (md+) |
|-------------|-----------------|---------------|
| 단순 확인 | `w-full max-w-[95vw]` | `max-w-[480px]` |
| 표준 폼 | `w-full max-w-[95vw]` | `max-w-[640px]` |
| 복잡한 폼 | `w-full max-w-[95vw]` | `max-w-[900px]` |
| 대형 데이터 | `w-full max-w-[95vw]` | `max-w-[1200px]` |

### 모바일 정보 밀도

| 모드 | 행 높이 | 폰트 | 터치 타겟 | 용도 |
|------|--------|------|---------|------|
| Mobile Compact | 44px | text-sm | 44x44px | 거래 내역 리스트 |
| Mobile Standard | 56px | text-base | 48x48px | 폼 입력, 설정 |

> 모바일에서는 데스크톱 Compact(28~32px)를 사용하지 않음 — 터치 타겟 44px 필수
