# 컨텍스트 관리 + 핸드오프 규칙

- **모델 버전에 의존하지 않는다** — 여기서 "메인 모델"은 현재 세션의 상위 모델을 뜻하며, 특정 버전명을 규칙에 박지 않는다
- 하네스가 컨텍스트를 자동 요약/압축하므로, 에이전트가 남은 컨텍스트 %를 스스로 정확히 측정할 수는 없다
- 핸드오프 트리거: **사용자가 컨텍스트 수치를 알려주거나, 사용자가 요청할 때만** 실행
- 수치 없이 "길어진 것 같아서" 감으로 핸드오프 호출 **절대 금지**
- SSOT: 장시간 작업 시 파일 아티팩트(스펙, 계획)를 진실 소스로 유지 — 압축 후 재주입 대상

| ctx 구간(사용자가 알려준 경우) | 행동 |
|---------|------|
| 0-60% | 정상 작업 |
| 60-75% | 논리적 작업 단위 완료 시 수동 /compact 제안 (사용자 확인) |
| 75-83% | 핸드오프 준비 제안 (자동 실행 금지, 사용자 확인 필수) |
| 83%+ | auto-compact 임박 구간 — 새 대규모 작업 시작 자제 |

## 참고: 하네스 자동 압축

Claude Code가 내부적으로 컨텍스트를 자동 요약한다. 우리가 제어할 수 없으므로 규칙이 아닌 **참고 지식**으로만 둔다.

**우리가 실제로 할 수 있는 것:**
- 사용자가 수치를 알려준 60-75% 구간에서 /compact 제안
- 장시간 작업 시 `.claude/handoff.md`에 상태 저장 (`/session-handoff`)
- 스펙/계획 파일을 SSOT로 유지 (압축 후 재주입)

> `session-handoff` 스킬의 트리거도 이 규칙과 일치시킨다 — "컨텍스트 % 자동 감지" 대신 "사용자 종료 의사 표현 시 또는 사용자 요청 시"로 발동한다.
